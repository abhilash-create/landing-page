Overview

How to create a landing page

Every landing page follows the same six-step process. Steps 1 and 2 are a one-time setup completed with your account team. Steps 3–6 are repeated for each new page variant.

00

Hero section

The hero is the first thing a visitor sees. Every element — eyebrow, headline, tagline, CTA note, stats — has a defined job. Weak or missing copy here is the leading cause of high bounce rates before users reach the plan card.

🏷
Eyebrow / urgency badge Recommended
Small label above the H1 — signals urgency, offer, or brand context
▾
Three patterns in use across the reference pages
PagePatternExample
index.htmlOrange pill badge with clock icon"Limited time offer — ends May 31"
landing_bBlue eyebrow text with decorative line"— Limited time offer"
landing_cMuted uppercase label with line"— Mobile plans —"
Rules
  • Font size: 11–13px, uppercase, letter-spacing ≥ 1.5px
  • Urgency copy must be truthful — use a real end date or remove the date entirely
  • If no active offer, use a brand/context label ("America's Best Network") rather than a false urgency claim
  • Margin below eyebrow before H1: 20–28px
  • Never use "Limited time offer" without a concrete end condition

Rules for tagline copy
  • Tagline max-width: 440–480px — do not let it span the full column width
  • Colour: muted / secondary ink — never as dark as the H1
  • Line height: 1.6–1.7 for comfortable reading
  • "No contracts. Cancel anytime." or equivalent must appear in the hero — this is mandatory reassurance copy
  • Offer note (discount callout) appears after the CTA button, not before it
  • Do not stack more than 3 subtext lines — use the features section for additional selling points

01

Coverage check

Every page variant must include a real-time coverage lookup. Users need to confirm the network reaches their address before committing to a plan — it is the #1 conversion blocker in carrier switching decisions.

📍
Required · all variants
Address input → live API → 5G / 4G LTE band result with visual indicators
▾
Why it is required

Coverage anxiety is the number-one stated reason users don't switch carriers. Showing real-time availability converts hesitation to intent. Pages that surface coverage before the CTA convert at more than twice the rate of those that don't. It also reduces post-activation churn from coverage dissatisfaction.

Minimum specification
ElementStandard
InputFull US address text field, autocomplete suggestions supported
APIPOST /api/coverage/check — token-authenticated
Result states✓ 5G + 4G LTE · ~ 4G LTE only · ✗ No coverage · ! Error
Band indicatorsVisual bars for 5G and 4G LTE with typical speed ranges shown
Error handlingNetwork timeout (15 s), address not recognised, international address
PlacementBetween trust bar and pricing, or directly below hero CTA
Implementation reference (from index.html / landing_b)
// Minimum working pattern async function checkCoverage() { await ensureToken(); // refresh on every call const body = { token, addressData: { type:'Service', address1, city, state, zip, country:'USA' } }; const res = await fetch('/api/coverage/check', { method:'POST', headers:{'Content-Type':'application/json'}, body }); // render band indicators for h5g / h4g booleans in response }
02

Compatibility check (BYOD / IMEI)

Users must be able to verify their existing phone works before purchasing a plan. BYOD capability reduces the perceived risk of switching.

📱
Required · all variants
15-digit IMEI input → compatibility check API → compatible / not compatible result
▾
Why it is required

A BYOD check directly before the plan CTA removes the single largest objection: "I'm not sure my phone will work." Every major MVNO conversion study shows device compatibility anxiety as a top cart-abandonment cause. Platforms that mandate it see measurably higher plan activation rates.

Minimum specification
ElementStandard
InputNumeric, maxlength="15", live character counter 0/15
ValidationExactly 15 digits, Luhn check recommended
ResultCompatible ✓ with device detail OR Not compatible with upgrade prompt
PlacementInside the "Bring your own device" section, adjacent to BYOD copy
Section headlineMust include "bring your own device" language and unlock guidance
Reference copy pattern (from index.html)

"If your current phone is unlocked and compatible with our network, you can bring it along — no worrying about losing your photos, videos, or data."

03

FAQ section

FAQs serve three conversion functions: pre-answer objections so users don't leave, reduce support volume, and signal transparency — critical for switching decisions.

💬
Required · all variants
Minimum 5 accordion Q&As — must cover the topics listed below
▾
Why it is required

FAQs pre-empt the "I need to search for more info" exit that silently kills conversions. Answering "what happens if I cancel?" and "does my phone work?" on the page keeps the user in the purchase flow. Each answered FAQ also deflects inbound support tickets.

Mandatory topics (must appear in every page)
Q1What is [Brand Name]? — value prop overview
Q2How do I keep my current number? (port-in)
Q3Can I bring my own device? (BYOD + unlock guidance)
Q4eSIM support — activation time, compatible devices
Q5Contracts & cancellation — zero ETF, month-to-month
Interaction requirements
  • Accordion style — one item open at a time
  • Tap / click target minimum 44px tall per row
  • Animated open/close (max-height or grid-template-rows transition)
  • Placement: above footer, below features section
04

Plan CTA button

The plan CTA is the single highest-leverage element on the page. It must be prominent, legible, and immediately actionable especially on mobile where 60%+ of acquisition traffic arrives.

🎯
Recommended · strong conversion impact
56 px height · full-width on mobile · price in label · pill shape preferred
▾
Why it matters

On mobile, sub-44 px tap targets cause misfire rates above 12%. Each misfire increases bounce probability. A full-width pill CTA with clear label copy including the price ("Get My $20 Plan") outperforms a compact button. The label must include either the price or a clear value signal — never just "Get Started".

05

Responsive layout

All pages must function correctly across viewport widths from 320 px to 1440 px+. Mobile-first thinking is mandatory — the majority of acquisition traffic is mobile.

📐
Required · all variants
Viewport meta tag + breakpoint grid + clamp() typography + no horizontal overflow
▾
Viewport meta — mandatory
<meta name="viewport" content="width=device-width, initial-scale=1.0">
Breakpoint grid (from index.html)
  • ≤ 1100pxHero switches to single column · feature grid → 2 col · two-col sections stack
  • ≤ 768pxSection padding reduces · plan card full-width · trust rating text hidden
  • ≤ 480pxInput/button height drops to 48px · hero CTA goes full-width · feat grid → 2 col compact
  • ≤ 360pxSingle column everything · minimum font sizes · nav logo shrinks to 36px
Typography — use clamp() for headings
/* H1 — scales between 28 px and 52 px */ font-size: clamp(28px, 4vw, 52px); /* H2 — scales between 22 px and 38 px */ font-size: clamp(22px, 3.2vw, 38px);
Checklist
  • No fixed-pixel widths on images — use max-width:100%
  • Overflow-x hidden on body
  • Coverage and BYOD inputs stack vertically at ≤ 480 px
  • FAQ accordion tap target ≥ 44 px tall
  • All form inputs minimum 48 px height at ≤ 480 px
  • Do not use position:fixed for non-nav elements on mobile
06

Trust signals

Social proof must appear above the fold, immediately after the hero. Real ratings from a named source only — no fabricated star counts or review numbers.

⭐
Required · all variants
Verified rating source + star display + review count + "Excellent" label
▾
Standard pattern (from index.html & landing_b)
  • Rating source must be named — Trustpilot preferred
  • Display numeric rating e.g. "4.5 out of 5 stars"
  • Include review count e.g. "based on 12,626 reviews"
  • Visual star row with half-star support
  • Placement: sticky trust bar below nav OR trust pill on hero image
  • No placeholder copy — if live rating unavailable, do not display the bar
07

Broadband facts label (FCC)

A consumer-facing broadband disclosure is legally required. It must be accessible from the plan card via a clearly labelled link or toggle.

📄
FCC Compliance
FCC-formatted label accessible from the plan card — all pricing information must match
▾
Required label fields
  • Monthly price (must match plan card)
  • Additional charges: cost recovery fee, activation fee, SIM shipping
  • Early termination fee (must state $0.00 if no contract)
  • Government taxes — "Varies by location"
  • Speeds: 4G LTE and 5G download, upload, latency
  • Data included + overage rate e.g. "$5.00/0.5GB"
  • Network management policy link
  • Privacy policy link
  • Contact URL
  • Unique Plan Identifier
  • FCC Consumer Help Center link
Placement

Accessible as either (a) an inline expand/collapse toggle below the plan CTA button, or (b) a modal opened from a "Broadband Facts" link. The label must be visually distinct — black border, monospace-style layout as per FCC guidelines.

08

Page structure & section order

All pages must follow this section order. This structure reflects the proven conversion flow used across all brand variants.

🏗
Required structure
Nav → Hero → Trust bar → Pricing → Features → BYOD → Network/Coverage → FAQ → Footer
▾
Section order with requirements
#SectionRequired content
1NavLogo only. Sticky. No outbound links or competitor distractions.
2HeroHeadline + plan price + primary CTA above the fold. Urgency badge optional.
3Trust barRating, star display, review count, source name. See §06.
4PricingPlan card: data, price, features, CTA, Broadband Facts. See §04 + §07.
5Features3–4 feature cards covering network, talk/text, contract-free, support.
6BYOD (Compatibility)IMEI input + result. See §02.
7Coverage checkAddress input + 5G/4G band result. See §01.
8FAQMin 5 accordions. See §03.
9FooterLogo + copyright + privacy + network management + contact links.
Nav and hero rules
  • Nav contains brand logo only — no navigation links that pull users away from the funnel
  • Sticky nav (position:sticky;top:0) with subtle bottom border
  • Hero headline must include the plan price (e.g. "Switch for Just $20/mo")
  • "No contracts. Cancel anytime." must appear within the hero section
  • Scroll-reveal animations allowed but must not delay CTA visibility by more than 300ms
Footer must include
  • Brand logo
  • Copyright line e.g. "Copyright © 2026 [Brand]"
  • Link to Privacy Policy
  • Link to Network Management Policy
  • Contact / support link
